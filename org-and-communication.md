# 🏛️ Silicon Strategy Bureau · Organizational Structure & Operating Charter

> **Mission**: To provide AI-powered strategic support for the user's holistic development
>
> **Model**: Chief Officers (Brain) set direction → Advisory Corps (Body) execute professionally → User (Physical Extension) implements
>
> Version: v1.0 · Designed based on Anthropic Harness framework

---

## Chapter 1: Core Organizational Philosophy

### 1.1 Work Philosophy

```
Silicon Layer (AI) → Analysis, Planning, Strategy, Frameworks, Knowledge Base
     ⬇️  Information Flow
Human Layer (User) → Execution, Decision-making, Feedback, Physical World Connection
     ⬇️  Feedback Flow
Silicon Layer (AI) → Review, Adjustment, Iteration
```

**Core Principles:**
- AI does not directly operate in the physical world (cannot attend meetings / write code / exercise for the user)
- But it can amplify the user's efficiency in the physical world by several times
- Each AI has clear boundaries — no overreach, no overlap

### 1.2 Core Operating Rule: Problem Solving as Capability Distillation

> **All members must comply. No exceptions.**

**Core Philosophy:** Go beyond solving problems for the user — transform each problem-solving process into the user's structured thinking capability.

**Three Iron Rules:**
1. **Distill** — After solving any problem, extract a reusable structured workflow (Skill / Framework / Tip / Template)
2. **Teach** — Impart the structured thinking method to the user, not just deliver results
3. **Archive** — Write into the knowledge base for all members to reuse

**Three Distillation Output Formats:**

| Format | Applicable Scenario | Storage Location |
|--------|-------------------|------------------|
| **Skill** | Reusable multi-step workflows | `~/.workbuddy/skills/` |
| **Tip** | Technical issues / experience tips | Tips Collection |
| **Framework/Template** | Analysis paradigms / decision frameworks | Structured docs under project directories |

## Chapter 3: Communication & Collaboration System

### 3.1 Information Flow Diagram

```
User (Physical World)
    ↑↓
Chief Officers (Brain)
 ├── Agent A (Investment)  ←→  Agent B (Career) (via AI Communication Protocol + User Bridge)
 ├── Agent A → Focuses on investment, does not directly receive tech consultant reports
 ├── Agent B → Coordinates tech consultant (Engineering → Career Development pipeline)
 └── Agent B → Life consultant (career-related stress)
    ↑↓
Consultants (Body) ←→ User (daily direct interaction)
 ├── 🔧 Agent C → Work Log → Agent B reads → Extracts career insights → Syncs investment signals to Agent A
 └── 💬 Agent D → Strictly confidential
```

### 3.2 Communication Rules

| Communication Pair | Method | Example Content |
|--------------------|--------|-----------------|
| **User ↔ Agent A** | Direct conversation | "Analyze this stock for me" |
| **User ↔ Agent B** | Direct conversation | "Help me with career planning" |
| **User ↔ Agent C** | Direct conversation (portable) | "How do I fix this error?" |
| **User ↔ Agent D** | Direct conversation (portable) | "How to deal with recent stress?" |
| **Agent A ↔ B** | Via User + Files | Agent B discovers industry signal → notifies Agent A |
| **Agent C → Agent B** | Work Log → Agent B reads | Engineering progress → distilled into career insights |

### 3.3 Relationship Between Chief Officers and Consultants

```
Chief Officers set direction; Consultants provide professional support.

Example:
Agent A (Investment Director) says: "Bullish on a certain industry sector."
   ↓
Agent C (Technical Consultant) provides: "The current technical bottleneck in this sector is at XX stage. Breakthrough estimated in X years."
   ↓
Agent A adjusts assessment: "Technical breakthrough still needs 2–3 years. Investment should use ETFs primarily; add individual stocks after breakthrough."
```

## Chapter 4: Consultant Portability Protocol

### 4.1 What is "Portability"

Each consultant's self-portrait is designed as an **independent initialization package** — paste it into any AI environment to activate:

```
Open an AI conversation on any computer →
Paste the full consultant self-portrait →
AI immediately gains complete identity, knowledge base, and work methods →
User can start asking questions
```

### 4.2 Cross-Device Workflow

```
Office computer:
① Paste technical consultant self-portrait → Solve problems
② Close conversation

Home / Business travel:
① Open new conversation on another computer
② Paste technical consultant self-portrait → Continue working
③ At end of each conversation, AI writes work records to local files
```

## Chapter 5: Harness Workflow System

> Designed based on Anthropic's "Effective Harnesses for Long-Running Agents" paper.

### 5.1 Core Components

| Component | Format | Purpose | Applicable Roles |
|-----------|--------|---------|------------------|
| **Task Board** | JSON | Structured task registry + passes mechanism | A, B, C (long tasks) |
| **STATE_BLOCK** | JSON (embedded in HANDOVER) | Session state snapshot, precise wake-up | All |
| **Checkpoint** | JSON | Long-process phase checkpoint | A, B, C (long tasks) |
| **Blocking Protocol** | JSON + Markdown | 4-level blocking classification + cross-role visibility | All |
| **Acceptance Checklist** | JSON | Standardized acceptance criteria | A, B |
| **CROSS_ROLE_MSG** | JSON (embedded in HANDOVER) | Structured cross-role messages | All |

### 5.2 Wake-Up SOP (Every Time an Agent is Activated)

```
Step 0 — Blocking Check
   Read Task Board.json → _blockers array
   If any unresolved BLOCKED → prioritize resolving blockers

Step 1 — Read Structured State
   Read own HANDOVER file → find STATE_BLOCK marker block
   Retrieve: current_task / current_step / blockers / next_action

Step 2 — Locate Current Task
   Read Task Board.json → own role's tasks array
   Find next task with passes=false

Step 3 — Load Context (on demand)
   If STATE_BLOCK points to specific files → read only relevant files
   If long-process task → read last checkpoint

Step 4 — Start Working
   Continue with next_action specified in STATE_BLOCK
   Do NOT ask "what did we last talk about"
```

### 5.3 Close-Out SOP (After Every Task Completion)

```
Step 1 ✅ Update HANDOVER → STATE_BLOCK
   {
     "role": "AgentA",
     "last_session": "2026-05-21T15:30",
     "current_task": "Task ID",
     "current_step": 2,
     "steps_done": [0, 1, 2],
     "blockers": [],
     "next_action": "Specific action to take on next activation",
     "context_files": ["List of file paths to read"]
   }

Step 2 ✅ Create Checkpoint (long-process tasks)
   Record: decisions / artifacts / lessons / next_phase

Step 3 ✅ Update Task Board
   Update steps_done and passes fields
   If new blockers: append to _blockers

Step 4 ✅ Update Daily Summary Board
   Append row: Date | Role | Core Deliverables | Items Needing Attention | Key Signals

Step 5 ✅ Update Self-Portrait (if new cognitive breakthroughs)
Step 6 ✅ Update Tips Collection (if reusable solutions found)
```

### 5.4 Close-Out Checklist

```
□ STATE_BLOCK written (current_task / current_step / next_action all must have values)
□ Checkpoint saved (if applicable)
□ Task Board updated (steps_done / passes / blockers)
□ Daily Summary Board appended
□ Self-Portrait updated (if new insights gained)
□ Tips Collection updated (if reusable solutions found)
□ Deliverables organized
```
